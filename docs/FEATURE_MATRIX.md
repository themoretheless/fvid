# Матрица функциональности Fvid
Codec-паритет с внешним «проигрывает всё» эталоном (K-Lite Codec Pack) измеряется отдельно:
`docs/KLITE_COVERAGE.md` и `scripts/validate_klite_coverage.py`.


Цель — покрыть и обогнать FFmpeg в фактической продуктовой области Fvid по проверяемым вертикальным сценариям. Ни metadata-инвентарь, ни наличие функции в подключённой библиотеке не считаются готовой функцией Fvid.

## Зафиксированная граница продукта

Граница выведена из публичных CLI/Rust API и существующей архитектуры, а не из уже пройденных тестов:

- Локальные конечные media files: анализ, stream mapping, remux/mux/demux, точный edit, decode и transcode. Вход не может быть URL или произвольным AVIO callback.
- Y4M stdin/file/stdout: bounded CPU, wgpu и CUDA crop/hflip/vflip pipelines, включая resident chains.
- Видео: spatial transforms, интервалы, сохранение timeline, software и NVDEC/CUDA/NVENC backends. Новые spatial/conversion filters входят в область; произвольный пользовательский filtergraph пока не является публичным контрактом.
- Аудио: stream copy, точный PCM edit и decode compressed audio в PCM. Совместный compressed-audio/video interval в `transcode-lossless` (AAC/MP3/FLAC→PCM, с optional `--seek`) квалифицирован.
- Container semantics: порядок/выбор потоков, time bases, metadata, disposition, chapters и subtitle passthrough. Subtitle burn-in пока является gap внутри области.
- Codec scope определяется codec families, для которых существует end-to-end workflow и corpus, а не полным списком `capabilities`. Расширение на HEVC/AV1/VP9/ProRes и hardware profiles остаётся частью цели.
- Не входят в фактическую границу текущего продукта: capture devices, streaming server, HLS/DASH packaging и distributed batch service. Окно проигрывания входит отдельно: `fvid play` / `fvid media play` принимает локальный файл или URL (`http`, `https`, `rtsp`, `rtmp`, `udp` и остальные схемы `PLAYBACK_PROTOCOLS`). Обработка (remux/decode/edit) по-прежнему только локальные файлы. Наличие capture/packaging в FFmpeg не считается gap данного аудита, пока публичная архитектура Fvid не добавит такой продуктовый сценарий.

Каждый элемент считается покрытым только при наличии публичного CLI/API, correctness/interoperability oracle и эквивалентного fair-pair benchmark. Для performance-покрытия требуется медиана Fvid строго быстрее FFmpeg более чем на 15%; единичный удачный запуск или benchmark другой операции доказательством не является.

## Реализовано и проверено

| Возможность | Исполнитель | Проверенная граница |
|---|---|---|
| Y4M 420/422/444 8-bit | Rust | parse, crop, hflip, vflip, malformed input |
| CPU views без промежуточного кадра | Rust | crop/vflip; hflip CLI пока материализуется |
| Metal GPU-фильтры | Rust + wgpu | Реальный M4 Max, byte equality, 4K |
| Цепочки GPU-фильтров без промежуточного RAM | Rust + wgpu | Metal, lifetime/reuse/counters; без codec interop |
| CUDA / DX12 (Windows) | CUDA / wgpu adapters | RTX 5090: byte equality vs CPU/FFmpeg; resident CUDA chains |
| CUDA / Vulkan / DX12 / GL (прочее) | CUDA / wgpu adapters | Реализация; Linux/прочие GPU — отдельная квалификация |
| Цепочки GPU без промежуточного RAM (CUDA) | Rust + CUDA | Windows RTX 5090; lifetime/reuse/counters; без codec interop |
| NVDEC → CUDA NV12 filter → NVENC | FFmpeg CUDA + fvid-cuda | Windows RTX 5090; `media hw-filter`; host_frame_copies=0 |
| MCP-модуль | rmcp + Rust handlers | 13 tools, stdio/локальный HTTP, CPU/media/Metal; без публичного deployment |
| Probe обычного файла | native libavformat adapter | MP4/MKV, streams, codec/profile/level, bitrate/rate, metadata, disposition, chapters, exact timebase |
| Remux без encoder/decoder | native libavformat adapter | MP4→MKV, MP4+AAC→MP4, SRT→MKV, mapped SubRip in MKV, packet equality |
| Выбор/удаление дорожек | native adapter | `--streams`; PCM audio extraction to WAV |
| Lossless-обрезка внутри GOP | decode → выбор PTS → FFV1 | H.264 B-frames, crop/vflip, retiming глав, packed PCM packet slicing; opt-in seek только video-only |
| Обрезка по времени | native adapter + строгий Rust-контракт | H.264 IDR без B-frames; closed-GOP H.264/HEVC RAP→RAP и mid-GOP pre/post-roll (точный packet `from`/`to`, end-RAP decode span); FFV1 keyframe; aligned PCM |
| Склейка | native adapter + строгий Rust-контракт | Совместимые H.264 / FFV1+PCM, точные seams |
| Декодирование H.264 / FFV1 | native libavcodec adapter | Для crop-lossless; включая B-frame drain |
| Проигрывание (нативное, без FFmpeg) | собственные demux/кодеки + eframe/cpal | `fvid play [INPUT...]`, где INPUT — локальный Y4M/MP4/MOV/WebM/MKV или `.m3u`/`.pls`-список, причём MP4 здесь и целый файл, и поток: индекс по `moof`/`traf`/`trun` вместо полной `stbl` читает тот же демувер (`index_fragments`, `a_fragment_of_audio_is_indexed_as_its_own_run_states`, `the_sound_a_fragment_indexes_is_the_sound_the_player_hears`, `the_picture_a_fragment_indexes_reaches_the_picture_route`); несколько входов образуют очередь, а файл только со звуком (MP4 `.m4a`, первичные ряды `.aac`, `.mp3`, `.flac`, `.ac3` и PCM-файлы, MKV/MOV без картинки) — тоже вход. Клавиатурное управление VLC: поиск стрелками 3/10/60/300 с (Shift/Alt/Ctrl-Cmd), Ctrl/Cmd+↑/↓ и колесо — громкость, M — mute, `=`/`-` — скорость 0.25×–4× без смены высоты тона (`audio::Stretch` читает кольцо участками по 256 кадра, которые играются в записанном темпе, а начало каждого ищет там, где волна продолжает предыдущий; часы идут по отпущенным кадрам, а не по найденным местам), `,`/`.` — та же скорость шагами по одной десятой внутри тех же границ (`rate_fine` держит её между крайними ступеньками, `the_fine_rate_walks_by_tenths_inside_the_ladder`), `\` — возврат к 1×, Home/End и цифры 0–9 — шкала времени, E — покадровый шаг (Shift+E назад), T/G/H и Alt+↑/↓, Alt+`=`/`-` — внешние субтитры, а Ctrl/Cmd+T загружает названный файл (`Pick` различает, для чего открыт выбор, `pick_subtitles` не открывает его без элемента, `add_subtitle_file` ставит прочитанное в конец списка источников и включает, `poll_dialog` опрашивает `AsyncFileDialog` на `Waker::noop`); сам файл читается в той кодировке, в которой написан — Byte Order Mark называет UTF-8 или UTF-16 сам, без него текст остаётся UTF-8, а если им не выходит, читается windows-1251, в котором до сих пор приходят кириллические рипы (`decode_text`, `a_windows_1251_file_reads_as_the_text_it_holds`), N/P — очередь, R — повтор Off/All/One, а S — Random: очередь идёт нарисованным циклом, где каждый элемент играет ровно один раз, `p` идёт назад по пройденному пути, а повторяющий список на пустом цикле раздаёт новый (`shuffle_forward`/`shuffle_back`, раздаёт `deal_cycle`; `a_cycle_is_dealt_over_the_whole_list_once`, `the_shuffled_list_walks_its_cycle_and_returns_its_steps`, `a_shuffled_item_running_out_walks_the_cycle`; `--random` начинает сессию уже перемешанной, `a_random_start_holds_the_cycle_the_queue_was_dealt`), L — участок A–B (`loop_press`/`loop_rewind`, перематывает к A при достижении B), J/K — задержка звука ±10 с с шагом 50 мс (`delayed_clock` сдвигает часы устройства в gate синхронизации), A/Shift+A — аудиодорожки файла (`audio_tracks` у контейнерного стрима, `track_step` листает их кольцом), B/Shift+B — субтитровые дорожки (`WebmSubtitleReader` и `Mp4SubtitleReader` собирают `Cue` из блоков `S_TEXT/UTF8`, `S_TEXT/ASS` и `S_TEXT/SSA` и сэмплов `tx3g`, `subtitles::cue_end` даёт реплике конец, а `subtitles::ass_block` ещё и вынимает из блока скрипта его собственный промежуток времени, если муксер оставил его в строке), `[`/`]` — главы, которые называет сам файл (`chpl` в `moov/udta` и атомы `Chapters`/`ChapterAtom` Matroska отдают одинаковый `Chapter { start_ns, title }`, `container_facts` выбирает читателя по первым байтам и для глав, и для тегов файла, `chapter_ahead` ищет первое начало впереди позиции и последнее позади неё, а на краю списка клавиша отвечает «Last chapter»/«First chapter» и не перематывает; времена Matroska читаются по `TimestampScale`, а список, который при ней уходит за длительность файла, — в наносекундах, как их пишет `ffmpeg`), Shift+S — снимок кадра в PNG (`src/snapshot.rs` пишет CRC-32/Adler-32 и stored-блоки DEFLATE сам, `snapshot_name` собирает имя из медиа-времени), `z`/`Z` — увеличение по четырём ступенькам меню VLC Zoom: 0,25×, 0,5×, 1× и 2× (`ZOOMS`, `zoom_step`), множитель берётся от уже вписанной картинки (`video_rect`), а увеличенный кадр тянется мышью (`pan`) не дальше, чем он сам нависает над краем. `c`/`C` — кадрирование по тому списку форм, который VLC держит в переменной `crop` (`CROPS`, `crop_step`, `crop_insets`): остаётся наибольшая центрированная область нужной видимой формы, а список начинается с целого кадра, так что та же клавиша возвращает его обратно; обрезанная часть идёт шейдеру координатами (`uv_window`), пиксели не перезаписываются. Границы, которые заявлены самим файлом, — `PixelCropLeft/Top/Right/Bottom` внутри `Video` дорожки Matroska (`Track::crop`, `Track::visible`, `insets` читателя, `container_insets` плеера), — уходят с экрана без меню: кадр декодируется целиком, форма меню измеряется по оставшемуся, и два кадра складываются от кодированных краёв внутрь (`shown_insets`), а кадр меньше своих границ показывается целиком. Бокс `clap` из MP4 не читают ни ffprobe, ни VLC (issue mpv 16278), поэтому игнорируется и здесь. `v`/`V` — пропорция по тому списку форм, что VLC держит в переменной `aspect-ratio` (`ASPECTS`, `aspect_step`, `shown_size`): кадр не обрезается, а те же пиксели рисуются в названной пропорции, и список начинается с формы самого файла, так что та же клавиша её и возвращает; `Fill` берёт форму окна. Кадрирование измеряется формой контейнера и применяется раньше: пропорция задаётся оставшемуся. Ctrl/Cmd+E — окно настроек картинки под тем же сочетанием, что у VLC в меню Tools (`Control::Effects`, `Adjust`, `adjust_scalars`): переключатель Enable и пять ползунков вкладки Adjustments с границами VLC — яркость и контраст 0…2, гамма 0.01…10, насыщенность 0…3, тон ±180°; числа складываются в пять, как их складывает фильтр adjust (прямая с закрепом чёрного и обратная гамма для яркости, поворот и растяжение хроматин вокруг серого для тона с насыщенностью), на GPU едут униформой и применяются к сохранённым отсчётам до любой растявки диапазона, а программный путь прогоняет пиксели через обратную матрицу 601 и те же формулы (`adjust_luma`, `adjust_rgb`); выключенный переключатель — единичный набор, кадр остаётся таким, каким декодирован, настройки живут до конца сессии, снимок пишет кадр без них. `i` — панель о том, чем элемент на экране является, которую VLC держит в отдельном окне Ctrl+I (`Control::Info`, `info_lines`): первыми — факты, которые контейнер знает о файле целиком: его имя, автор, автор альбома, альбом, номер дорожки, диск, жанр, издатель, правообладатель, год, комментарий, описание и рейтинг, который из двух контейнеров один только Matroska и держит (`Mp4Reader::tags`, `WebmReader::tags`, `FileTags`); номера дорожки и диска — единственные нечисловые на вид факты: в MP4 боксы `trkn` и `disk` держат два числа по два байта, и читатель собирает `3` или `3/12` с обеих их записей (`pair_text`), автор альбома пишет бокс `aART`, а издателя и рейтинга MP4 не знает — `ffmpeg` бросает оба их тега при записи; Matroska читает текст под `TRACK`, `TRACKNUMBER` и под именем `PART_NUMBER`, которым пишет тег ffmpeg-муксер, под `DISC`, `DISCNUMBER`, `ALBUMARTIST`, `ALBUM_ARTIST` и `PUBLISHER`, а также под `COPYRIGHT`, `DESCRIPTION` и `RATING` (в MP4 atom-ы первых двух называются `cprt` и `desc` без знака авторского права), кодек картинки (`video_codec`, таблица `mp4_codec` для fourcc MP4/MOV и `codec` читателя Matroska), её кодированный размер и частота (`fps_text` — та же, что пишет подпись под заголовком), заявленная контейнером форма пикселя, кодек звучащей дорожки — одним словом, как его называет зритель (`sound_codec` сводит `mp4a`, `A_FLAC`, `sowt` и dispatch-имена декодера к `AAC`, `FLAC`, `PCM`, незнакомое написание остаётся как его назвал контейнер; имя снято с открытого потока, поэтому клавиша дорожки меняет его вместе со звуком), место звуковой и субтитровой дорожек в тех списках файла, из которых их выбрала клавиша, размер файла с его длиной и складывающимся из них битрейтом (`file_size`, `byte_size`, `bitrate_text`) и число названных глав. MP4/MOV пишет их боксами `©nam`, `©ART`, `©alb`, `©gen`, `©day`, `©cmt` в `moov/udta` — текстом прямо в боксе или в написании через `meta/ilst` (`read_tags`, `tag_text`); Matroska — в `Title` блока сведений и в `TITLE`, `ARTIST`, `ALBUM`, `GENRE`, `DATE`, `COMMENT` тега всего файла, но не отдельной дорожки (`read_tags`, `FileTags::insert`), а список тегов обходит терпимо к чужим для читателя байтам (`fields_to_first_gap`, `lenient_text`) — файл, который себя не назвал, остаётся без строки. Из файла при этом не читается ничего: и размер, и эти факты сняты один раз при открытии элемента — тем же вторым проходом, что и главы, панель переживает смену элемента и, пока открыта, держит остальное управление видимым (`controls_visible`). Опции запуска первого элемента: `--start-time`/`--stop-time` (`parse_clock` принимает секунды и `Ч:М:С`) и `--rate` 0,25×–4× (`parse_rate`); неизвестная опция или опция без значения — ошибка запуска. На всю сессию держатся `--start-paused` (`hold_start` просит ровно один кадр, чтобы окно не осталось пустым, и ждёт пробел), `--no-audio` (звуковая дорожка не открывается вовсе, а файл без картинки отвергается с указанием на опцию) и `--audio-track`/`--subtitle-track`, считающие с единицы, как сообщения плеера; число, до которого список файла не дотягивается, оставляет первую дорожку. `--volume N` (проценты от 0 до 200, `parse_volume`), `--mute`, `--loop`/`--repeat` (то же `Repeat`, что листает клавиша `r`), `--random` (тот же Random, что включает `s`), `--audio-delay` и `--subtitle-delay` в миллисекундах до тех же ±10 с, что и клавиши (`parse_delay`), и `--sub-file FILE` держатся на всю сессию; названный файл субтитров идёт впереди угаданного по имени видео, а из нечитаемого плеер отвечает «Cannot read subtitles» и не откатывается молча. `--zoom F` держится на всю сессию: множитель картинки от 0,25 до 10 (`parse_zoom`), в ступеньки меню попадать не обязан, а первая `z` уводит на соседнюю. `--crop ФОРМА` держится так же: два числа через двоеточие — обычные или в сотых (`185:100`), либо `none` (`parse_crop`). `--aspect ФОРМА` держится так же: те же два числа, либо `default` и `fill` (`parse_aspect`, общая с кадрированием `parse_ratio`). Пять настроек картинки держатся так же: `--brightness`/`--gamma`/`--saturation`/`--contrast`/`--hue` в границах своих ползунков VLC (0…2, 0.01…10, 0…3, 0…2, ±180°), и называние хоть одного включает Enable, как у VLC вместе с его фильтром (`parse_setting`, `Adjust` в разобранных аргументах). Звук: MP4/AAC-LC+PCM и Matroska/Vorbis+MP3+FLAC+PCM на отдельном потоке, часы устройства придерживают картинку (`AUDIO_SYNC_SLACK` = 50 мс), усиление и скорость считаются в device callback, а скорость — стретчем того же кольца (`Ring::read_stretched`), поэтому 1× читает кольцо тем же `Ring::read`. Файл без декодируемой картинки играется как элемент только со звуком: позицию шкалы держат часы потока (`AudioPlayback::position`), длину — `AudioStream::duration` (MP4 из `mdhd` в тиках своей таймскейлы, Matroska из меток блоков и `DefaultDuration`), сцена показывает ноту; перемотка, шкала, скорость, громкость, дорожки, A–B, `--start-time`/`--stop-time` и автопереход очереди работают, покадровый шаг и снимок отказывают (`No picture`, `Nothing to save`). Субтитры — текстовый sidecar `.srt`/`.vtt`/`.ass`/`.ssa`, который разбирает собственный парсер (`src/subtitles.rs`) без libass и без стилей ASS, и текстовые дорожки самого контейнера: `S_TEXT/UTF8`, `S_TEXT/ASS` и `S_TEXT/SSA` в Matroska (`src/playback_webm_subtitles.rs`), где тайминг реплики берётся из блока, а у дорожки скрипта ещё и из строки `Dialogue:`, но только когда та называет настоящий промежуток (обнулённые метки значат «решать контейнеру»), и `tx3g` в MP4/MOV (`src/playback_mp4_subtitles.rs`), где начало и длина приходят из `stts`, а сэмпл — одна строка с 16-битной длиной впереди; какой читатель открыть, решает первые четыре байта файла. Перемотка есть там, где контейнер называет опорные кадры: MP4 по флагу `sync` таблицы сэмплов, Matroska по `keyframe` блока (`WebmVideoReader::seek_to_sync` пересобирает декодер и прокручивает пре-ролл), а цель накрывается целым интервалом кадра, так что вперёд точного попадания остаётся один шаг. Для Y4M произвольной перемотки нет. Форма пикселя берётся у контейнера, а не у декодера: MP4 читает `pasp` внутри визуального sample entry, а без него делит нарисованный размер `tkhd` на кодированный, Matroska читает пару `DisplayWidth`/`DisplayHeight` и только пока `DisplayUnit` считает их пикселями; `Track::pixel_aspect` и поле MP4-дорожки доходят до `NativeReader::pixel_aspect`, где `display_size` растягивает по ним ширину при вписывании картинки, оставляя высоту кодированной. Файл, который ничего не заявил, остаётся с квадратным пикселем. Поворот берётся из той же `tkhd`: ровно один из четырёх углов по 90° читается как поворот, а отражение, масштаб и наклон поворотом не считаются; `NativeReader::rotation` его отдаёт, а `fill_rgb` и `rotate_planar8` доворачивают и RGB-байты, и плоскости прежде, чем картинка вписана, снята в PNG и подписана размером `W×H`, — так что и вписывание, и подпись, и снимок говорят уже о стоящей прямо картинке. ## Текущий доказательный gap-аудит

Снимок 2026-09-20; статус относится только к текущему working tree и зафиксированным артефактам:

- Formats/mux/demux: MP4, Matroska, MOV, MPEG-TS, WAV и standalone SRT имеют квалифицированные remux/probe slices. AAC/MP3/FLAC квалифицированы как audio decode inputs. WebM проверен через VP9 transcode. Остальные форматы из whitelist и `capabilities` доступны библиотеке, но не считаются покрытыми без corpus.
- Codecs: H.264 decode/transcode, FFV1, libx264, libx265 lossless, lossless VP9, HEVC/AV1/ProRes decode→FFV1 crop, AAC/MP3/FLAC decode и packed PCM имеют end-to-end evidence. HEVC decode имеет fair-pair >15%; plain AV1 decode пока только correctness (dav1d уже слишком быстр для wrapper-delta). 12-bit `yuv420p12le` crop квалифицирован; hardware decode profiles и произвольные encoder combinations не квалифицированы.
- Edit/transcode: remux, stream selection, strict trim/concat (включая open-GOP start stream-copy), lossless and explicit-encoder transcode with secondary-video remux (full-duration; interval для non-reordered и closed-GOP H.264/HEVC secondary с RAP/mid-GOP, включая `--seek` через dedicated demuxers), exact video/PCM intervals, compressed AAC/MP3/FLAC decode during lossless video intervals (включая `--seek`) и VFR preservation реализованы.
- Video filters: large CPU V→V corpus in `scripts/validate_media.py` with pixel-exact FFmpeg fair-pairs — geometry (crop/flip/scale/epx/hqx/xbr/super2xsai/transpose/rotate/pad/field/stereo3d/tile/untile/fillborders/scroll), deinterlace/field packing, denoise/blur/sharpen (`median=`/`dblur=`/…), color/keying, range (`limiter=`/`setrange=`), temporal (fps/minterpolate/telecine/pullup/decimate/mpdecimate/framestep/amplify/lagfun/tblend/tmix/reverse/loop/select/thumbnail), timeline/aspect (`setpts`/`settb`/`setsar`/`setdar`), `noise=` (seeded), `normalize=`/`premultiply=inplace`, overlay/xfade, colorspace/tonemap/zscale+`--pix-fmt`. NV12 crop/flip subset on CUDA codec surfaces. **Still open:** Dolby metadata corpus, GPU scale, VideoToolbox↔Metal (P0, macOS), sparse specialty filters, and CPU speed-gate pairs for many newly added filters.
- Audio filters: sample-exact extraction/interval, PCM packet slicing, sample-rate conversion (`--rate`), channel rematrix (`--channels` / `-ac`), linear volume (`--volume` на float PCM), `mix-audio` с N≤16 inputs и `--weights` (`amix`), two-input `merge-audio` (`amerge`), `loudness` (`ebur128` measure) и `loudnorm` apply → float WAV (включая `--dual-pass` measured linear) реализованы. Gap synthesis отсутствует.
- Metadata/subtitles: probe, preservation, chapter clipping, SubRip passthrough, remux metadata set/delete, SRT→ASS `convert-subtitles` и external SRT `burn-subtitles` (libass/`subtitles=`) реализованы. Attachment mapping corpus и advanced styling остаются.
- Performance: [randomized/interleaved native CPU gate](../benchmarks/cpu-media-gate.json) проверяет пары по 21 раунду (paired within-round deltas), включая VFR identity, neighbor scale, transpose, rotate, pad, audio resample/channels/volume/amix/amix3/amerge, metadata remux, HEVC decode, SRT→ASS convert и subtitle burn-in; все проходят строго >15%. Compressed-audio intervals также имеют проходящие gates. [CUDA gate](../benchmarks/gpu-media-gate.json) проверяет семь пар по перемешанным внутрипарным раундам и принимает только hash-связанный correctness report: все семь проходят строго >15% (multi-session NVENC для encode-heavy identity/crop/hflip/cut; soft vflip и fused — single-session). Полный CPU+GPU performance gate доказан на **текущем** gate corpus; many new validate filters still lack dedicated >15% speed pairs.
- Профиль RTX 5090 на single-session H.264 упирался в один NVENC engine; multi-session timeline split + concat использует несколько engines без SFE (SFE не поддерживает H.264). Gate из-за этого не ослаблялся.

Следующий обязательный порядок: P0 VideoToolbox↔Metal (macOS) и GPU scale; codec/hardware corpus expansion; CPU speed-gate pairs for new filters; затем полный coverage-аудит. Validate≥569 (`scripts/benchmark_cpu_media_gate.py`); CPU/GPU gates green on existing pairs. Goal completion not defensible while remaining P0/P1 product slices are open.

## Как читать capabilities

`fvid media capabilities` перечисляет компоненты фактически установленного FFmpeg. В текущем снимке: 359 demuxers, 184 muxers, 527 decoders, 190 encoders, 481 filters. Это доступность **библиотеки**, а не 1741 реализованный и протестированный workflow Fvid. Наоборот, публичные операции Fvid перечислены в первой таблице, с их фактическими ограничениями.
