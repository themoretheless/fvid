# Protected/resilient AAC22.2 verification

This extends the configuration13 implementation in5e5f059b99 into the previously
unverified ESC/protection paths. It adds authored fixtures and acceptance,
not new production DSP or a claim of complete codec conformance.

Eight ELD programmes cover480/512 core samples and resilience flags0/1/4/5
(bare, HCR, section resilience, both) with56 separately protected EP3 classes.
Class transmission order is reversed relative to codec instance order. Each
has MP4 and Matroska acceptance plus an intentionally class-CRC-damaged MP4.
The invalid movies reach `EP class CRC mismatch` after two valid AUs. A native
retry of the correct AU matches the uninterrupted control and checkpoint replay.
Refusing these malformed CRC movies is distinct from accepting valid media.

Eight further programmes cover RVLC flags2/3/6/7 at both core sizes using EP1:
80 logical instances per AU are carried in40 consecutive-instance groups.
Two LD-SBR/CRC programmes carry84 instances in42 groups at480/512 core samples
and48kHz double-rate output, retaining both LFEs independently.
No invalid >63-class EP3 header is invented to represent these EP1 programmes.

EP1 groups are submitted in reverse dependency order, have exact non-byte
boundaries with deliberately nonzero ignored storage padding, and use different
but equivalent rational timebases. Signed negative initial PTS is retained.
Tests compare both complete PCM and rational PTS/duration with the logical
control. Omitting the root group fails without advancing decoder history.
Native checkpoint replay is checked for every AU.

The EP1 MP4s carry all consecutive instances in one AU of the AAC track;
reader playback uses `decode_source_packet` to supply typed ESC input. These
movies accept through public export and live MP4 rewind/seek. This is not a
40/42-track MP4 test, and no EP1 Matroska transport claim is made. EP3 movies
accept through public/owned MP4, owned Matroska and both live readers.

All18 programmes contain four authored nonzero AUs. The eight deliberately
invalid CRC companions are additional failure fixtures. The66-file corpus is
regenerated explicitly and byte-identically. It uses no private media, external
decoder, FFmpeg, subprocess or network. Ordinary tests only read saved fixtures.

The independent ELD oracle is direct sparse4N cosine/window/overlap; resilience
variants have unique generator names and separate scalar files. The LD-SBR
oracles reuse the independently generated authored22.2 scalar corpus. Their
logical packet bytes are asserted identical before using the first four AUs'
oracle samples. No decoded FVid PCM is used to generate an oracle.

The tests compare952320 float scalars within1e-7 full scale, without time,
channel or gain fitting. The EP3 cases match their scalar files exactly.
Group/native PCM also matches the uninterrupted logical control byte-for-byte.
Seek targets include sub-frame, frame, EOF and backward positions, plus rewind.

Three actual macOS `audio_probe --play-device` runs cover EP3 HCR+section,
EP1 RVLC+HCR+section, and EP1 LD-SBR/CRC. Full playback,25%/60% seek and rewind
complete EOF drain for all12 phases. These short device tests verify scheduling
and stereo routing, not a physical24-speaker setup or subjective audio quality.

This closes these protected-transport qualification cases for indexed22.2;
production code already implemented their configured element sequences.
It does not prove every prediction/window/SBR/profile combination. In particular,
RVLC combined with LD-SBR is not qualified by the separate cases above; the subsequent `aac-22-2-sbr-resilience-2026-11-01.md` records that combined qualification. The
LD-MPS unequal-HRTF, EBQ and fragment-association gaps remain open, as does the
full codec-gap objective.

Explicit reproduction (generation remains separate from ordinary tests):

```sh
python3 scripts/generate_aac_22_2_esc_fixtures.py
cargo --config profile.dev.package.fvid-media.opt-level=2 test --offline \
  --no-default-features --features player --test aac_22_2 --test aac_22_2_esc
```

The combined `aac_22_2`/`aac_22_2_esc` check passes six tests, zero failures or
ignored tests. The31-file base corpus and66-file protected corpus remain
separate. This extension's three new tests add18 programme variants; repeated
execution of the three base tests is not counted as new coverage.

The earlier86-target LD/ELD run has now finished with exit0:384 tests passed,
zero failed/ignored. It began before the AAC22.2 source changes and some test
binaries were replaced by later targeted builds during execution. Accordingly
it is not claimed as complete-current-tree qualification. Its exact targets,
exit result and log hash are preserved in
`aac-ld-eld-earlier-run-2026-11-01.json`.

All66 files also regenerate byte-identically with `subprocess.Popen`,
`socket.socket` and `socket.create_connection` replaced by failing sentinels.
This is a checked generator property, not an ordinary-test dependency.
