# Owned AAC indexed22.2 playback

Configuration13 is now admitted as24 coded channels in the owned ASC parser,
ordinary native decoder, LD and ELD configured element sequences, LD-SBR
association and the separate-ESC configured-layout tables. There is no new
foreign decoder or FFmpeg/libav dependency.

The16 elements include six SCEs, eight CPEs and two LFEs. Both LFEs appear
before the upper/bottom layer elements. PCM retains all24 channels in explicit
normal/top/bottom and front/side/back/LFE order, center before pairs. The two
LFEs are separate. A zero WAVE mask is intentional: a32-bit mask cannot name
all roles. `channel_positions()` supplies the full ordered placements, and
MP4 normalization retains the same opaque-position identity. Stereo routing
uses those positions and excludes both LFEs; it does not assume the first
24 WAVE bits or drop channels after channel8.

The top-side group's center is the overhead speaker. Its left/right members
are top-side speakers. The bottom group is front-center/left/right.

## Actual failures and fixes

The new authored movie first reproduces the previous ASC refusal specifically:
`unsupported AAC channel configuration`. With only layout admission enabled,
it exposes two further failures:

* ER-LC refuses the final CPE with `duplicate AAC element tag`. Internal ER
  ordinal tags were1..16, while the tag set accepts0..15. The final ordinal now
  uses the unused zero slot. Existing shorter indexed layouts retain their
  previous internal ordinals; signalled PCE tags are unchanged.
* LD-SBR's second LFE receives the first LFE's filter history. Its first output
  sample is0.000110088484 instead of the scalar oracle's near-zero sample.
  The previous owner contained one optional LFE DSP. It now owns one DSP per
  configured LFE, visits/counts their vector and payloads, resets each and clones
  each for checkpoints/transactions. A malformed final SBR group cannot commit
  either LFE's trial history.

The before-admission and intermediate failure logs are recorded by SHA256 in
the validation JSON. The same tests become acceptance with these fixes.

## Authored independent evidence

`generate_aac_22_2_fixtures.py` explicitly generates14 programmes, each six
nonzero AUs, in short MP4+VP9 and Matroska+VP9 videos. No private source media,
frames, audio or codec parameter sets are used. No network, FFmpeg, subprocess
or external decoder is needed for generation. Ordinary tests only read the
checked-in31-file corpus and do not generate fixtures.

The programmes cover Main, LC1024/960, LTP, ER-LC, ER-LTP, LD480/512,
ELD480/512, and ELD/LD-SBR480/512 with and without CRC. Ordinary Main/LTP
cases signal no prediction; LD cases exercise the independently authored lag
and window histories. LD-SBR cases use48kHz double-rate output with ordinary
constant envelopes, and both LFEs bypass HF generation. This is explicit
qualification of these programmes, not every tool/profile combination.

The scalar oracles use direct sparse cosines, authored amplitudes, normative
windows and independent overlaps. LD reuses the separate scalar lag oracle;
ELD uses its separate4N window/cosine owner. LD-SBR independently composes
CLDFB analysis, HF generation and synthesis per channel, treating both LFEs as
independent low-band-only inputs. No owned decoder output is the PCM oracle.

All1,723,392 scalar comparisons agree within1e-7 full scale, with observed
maximum2.3283064e-10. Every role is nonzero. Tests check the exact ordered
position metadata and authored stereo coefficients, native checkpoint replay,
failed-prefix retry, late-SBR failure rollback, joint retained-payload counting,
public/owned MP4 PCM, Matroska PCM, both live readers' rewind and sub-frame,
frame and EOF seeks. No time/gain/channel fitting is used.

Four actual macOS output-device runs cover LC, LD and both LD-SBR frame sizes
(including CRC). Each completes full playback,25% seek,60% seek and rewind
through EOF drain:16 phases. This verifies device scheduling and stereo routing,
not a physical24-speaker installation, subjective listening or sustained fps.

## Syntax references and scope

The pinned FDK source table `channel_configuration_13` independently confirms
the element sequence and `sc_chan_config_tab` confirms24 channels/six SCEs/eight
CPEs/two LFEs. The public upstream AAC layout table explicitly labels the same
coded elements' speaker roles:
https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavcodec/aac/aacdec_tab.c

These are research references. FVid stores its own explicit PCM ordering and
uses its own decoders; neither source is invoked at runtime or in ordinary
tests. Source hashes for the locally inspected pinned FDK files are in JSON.

The full codec-gap objective remains open. These fixtures do not qualify every
22.2 prediction/resilience/SBR/SSR combination, nor close the separate LD-MPS
unequal-HRTF, EBQ and replaced-fragment gaps. The previously launched broad
LD/ELD run uses the preceding build and is not evidence for this new source
change; current-source regression checks are recorded separately.

Current-source verification passes29 tests, zero failures/ignored, across
`aac_22_2`, `aac_eld_sbr`, `aac_eld_sbr_downscaled`, `aac_ld_layout`,
`aac_device_layout` and `aac_height_layouts`. Regenerating all31 fixture files
leaves them byte-identical. The reference JSON records logs, source pins and
exact qualification counts. Explicit reproduction:
