# Приоритет: обрезка, кроп и склейка без потери качества

Уточнение пользователя: «без копирования» означает отсутствие лишних копий **в памяти**. Итоговый видеофайл можно создавать; проект со ссылками на исходники не является обязательным результатом.

## Обязательный контракт

Каждая операция заранее сообщает, сохраняются ли сжатые данные, сохраняются ли декодированные сэмплы и где требуется материализация. Запрос без потери качества никогда не превращается автоматически в lossy-перекодирование. «Визуально почти одинаково» не означает lossless.

| Операция | Основной путь | Ограничение |
|---|---|---|
| Обрезка по времени | Demux → выбор ссылок на packets → пересчёт времени → mux | Нужны допустимые границы декодирования и корректная обработка зависимостей, PTS/DTS и аудио |
| Склейка | Последовательный обход совместимых packet streams без декодера/энкодера | Проверяются codec configuration, состав потоков, временные шкалы, геометрия/цвет, audio delay/padding и швы |
| Кроп декодированного кадра | Представление исходных planes/surface + область видимости | Потребитель должен принимать strides и область; упаковка может потребовать материализации |
| Экспорт физически обрезанного изображения | Decode → crop view → lossless encoder → mux | Побайтно сохраняются выбранные декодированные сэмплы; размер файла может вырасти, совместимость ограничена кодеком |

Streamcopy не выполняет фильтры декодированных кадров. Для зависимых кадров точное начало/окончание не гарантируется одним выбором packet timestamps. Это подтверждено документацией [streamcopy](https://ffmpeg.org/ffmpeg.html#Streamcopy) и [concat/inpoint/outpoint](https://ffmpeg.org/ffmpeg-formats.html#concat).

До экспорта план обязан различать:

- **Сохранение сжатых данных:** никакого decode/encode. Проверяются независимая декодируемость и требуемые границы. Если точная граница невозможна, возвращается причина и ближайшая допустимая граница; самовольного сдвига нет.
- **Сохранение сэмплов:** точный диапазон кадров/аудиосэмплов и выбранная область, без потерь относительно декодированного источника. Нужны квалифицированные декодер, lossless encoder и неизменные bit depth, subsampling, range и color metadata. Lossless-кодек не отменяет потери от промежуточного преобразования цвета.

Smart rendering с перекодированием пограничных GOP — отдельная будущая возможность. Обычное lossy-перекодирование даже двух GOP не удовлетворяет строгому требованию пользователя. Одного признака keyframe также недостаточно для универсального доказательства независимости сегмента.

Кроп через metadata потенциально сохраняет bitstream, но зависит от контейнера, кодека и проигрывателя. Он не вырезает скрытые пиксели физически и не заменяет универсальный экспорт. Такой путь требует отдельной квалификации; сейчас не реализован.

## Отсутствие лишних копий

`PacketRef` в будущем удерживает неизменяемый buffer владельца. Обрезка меняет диапазон и временные метаданные, склейка — порядок обхода. Пока muxer принимает этот buffer, промежуточный payload не клонируется. Если меняется упаковка битового потока или API требует другой storage, план показывает эту границу.

`FrameView` уже заимствует входной CPU-кадр. Кроп меняет координаты строк, vflip — порядок строк, hflip может передаваться как направление обхода. Rust lifetime не позволяет переиспользовать входной buffer, пока представление ещё используется. Между операциями не нужно создавать новый кадровый массив. Потребитель, принимающий только упакованный кадр, остаётся явной границей материализации.

GPU-путь теперь удерживает кадры между отдельными фильтрами: `GpuPipeline` / CLI `--then` не выполняют промежуточных host transfers. Финальная выгрузка в Rust API явная. Для Y4M остаётся по одной загрузке и выгрузке на границах цепочки. Следующая незавершённая граница — decoder/encoder surfaces: [подробный статус](GPU_RESIDENT.md). Перенос простой операции на GPU сам по себе не является оптимизацией.

Запись в файл, I/O-буферизация, работа драйвера и физическое перемещение данных устройством учитываются отдельно. «Ноль промежуточных кадровых копий» не означает отсутствие любого перемещения байтов во всей ОС.

## Что реализовано сейчас

- `Plan::view` / `FrameView` / `PlaneView` / `RowView`: CPU-представления без копирования payload, включая направление hflip.
- CPU CLI для Y4M без hflip записывает исходные строки напрямую: identity, crop, vflip и crop+vflip не создают выходной кадровый buffer. Для полного forward-plane используются крупные последовательные записи.
- Для hflip CLI пока сохраняет существующий материализуемый выходной кадр; GPU-пути также сохраняют свои allocations/transfers.
- Payload budget CPU равен входному кадру плюс выходной только для hflip. Публичный `Plan::new` по совместимости сохраняет консервативную проверку двух буферов; streaming API выполняет admission по фактически выбранному backend.
- Тесты проверяют адреса: байты, переданные CPU writer, принадлежат тому же buffer, в который reader прочитал кадр. Проверены 420/422/444, crop, vflip, повторные кадры, точность сэмплов и бюджет ровно одного кадра.

Добавлен [native media adapter](MEDIA.md): remux/stream selection, строгие trim/concat, декодирование H.264/FFV1, crop view и FFV1 lossless encoder. Проверены PCM/AAC, 8/10-bit samples и главы для операций полной длительности. Это не универсальная обрезка любых B-frame/GOP/audio-delay потоков; неподтверждённые случаи отвергаются. FrameView собственного Y4M-ядра и native codec path остаются разными исполнителями.

## Следующая последовательность

1. Выполнен первый demux/mux adapter: MP4/MKV, refcounted packets, timebase и codec configuration.
2. Выполнены строгие streamcopy trim/concat на квалифицированных независимых границах. Следующий блок — reordered/B-frame зависимости.
3. Выполнены проверки aligned PCM и полного AAC remux; произвольные delay/padding и аудиошвы остаются следующей работой.
4. Выполнен точный кроп с FFV1 lossless export. Точный lossless trim произвольных потоков ещё не реализован.
5. GPU surface interop только после измерения копий на полном сценарии.

Критерии приёмки: сохранённые packet payload/codec semantics для streamcopy; точные frame/audio samples для lossless; правильные PTS/DTS и швы; bounded memory независимо от длины видео; отсутствие промежуточных full-frame allocations там, где применимы views. Скорость измеряется только вместе с этими проверками.
