# Native WAVE IMA ADPCM admission

The original source at a33e7cdafde9af2d530ab507bd8e712ff99f5840 rejects format tag 0x0011 before decoder creation. The exact final six-test stand on that source passes the independent RIFF PCM/video control and fails five IMA gates. `baseline.json` identifies the original and restored candidate source hashes. The guarded baseline temporarily replaces only the owned wav.rs file, checks against concurrent changes, and restores the candidate in a finally block.

Microsoft/IBM primary specification, *Multimedia Data Standards Update* revision 3.0 (1994), “Fact Chunk” and “DVI ADPCM”: https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/Docs/RIFFNEW.pdf . The fact count states the decoded length in samples; combining it with the sample rate gives duration. The adapter admits four-bit mono/stereo IMA WAVEFORMATEX with a complete samples-per-block extension and geometry shared with the existing decoder. The pre-existing owned IMA block reconstruction is unchanged.

Thirty-six cases cover mono/stereo, short blocks and blocks longer than the 2048-frame scheduling grain, complete and absent fact counts, and positive fact counts clipping final coded padding. Identical coded bytes are wrapped in RIFF, RF64 and Wave64. Payloads are invented: a predictor with step index four and zero/sign-only codes makes four analytic unit steps and then stays constant. Independent signed PCM16 controls and literal f32 oracles determine every output sample. The source exposes the declared precision of four coded bits while decoded output stays float32.

Positive fact counts cap presentation and the last packet's duration; absent or zero counts leave the complete block geometry authoritative. Stored bytes are still charged before presentation trimming. A packet always contains complete blocks, even if one block exceeds the ordinary scheduling grain. Truncated complete-block prefixes play exactly their available decoded samples and fail EOF for the original data declaration. For the legacy unknown-length RIFF data marker, an unfulfilled positive fact count still fails EOF; its formerly successful EOF was reproduced on the intermediate candidate and is recorded in unknown-before.log. This is part of completing this capability, not an additional ID. Incomplete blocks, contradictory format geometry and impossible complete-file fact counts refuse; a corrupt step index is separately proved to reach the existing decoder's specific failure.

Native clocks, encoded block bytes, exact seek suffixes around block/window boundaries, EOF/MAX, rewind, decoder refusal and 144 actual playback-worker sessions are exercised. Native player file-factory dispatch is also checked for the three WAVE envelopes. No physical audio device or performance claim is made.

FFmpeg 9.0.2 matches all 24 full-block/absent-fact cases byte for byte. It emits seven additional padded frames in all 12 shortened-fact cases. libsndfile 1.2.2 matches 8/8 corresponding RIFF full-block/absent-fact cases and also emits padded tails in its four shortened-fact cases; all its decoded prefixes match the analytic oracle. Both diagnostic reports are retained in full. Neither external decoder is used as an oracle for fact-based clipping, and the stricter count/PCM expectations are retained. Ordinary Rust tests use checked-in fixtures and need neither reference decoder, FFmpeg, generation nor network.

Compatibility: existing function signatures and PCM/G711/predictive routes remain unchanged. The public `playback_wav::Coding` enum gains `ImaWav { block_bytes, block_frames }` so public Pcm geometry describes the actual coding. Downstream exhaustive matches must handle that variant (or add a wildcard); use Pcm methods for generic block geometry and codec dispatch. This is the only public migration required by the format capability.

The separate `mp4-subtitle-equal-pts` audit was rejected: its proposed witnesses hit the pre-existing nonterminal-zero STTS refusal before subtitle extraction. It changes no product code and contributes zero accepted IDs.

Initial qualification logs and the initial zero-test exact-filter launch are retained as diagnostics; only the final executed-test gates and repeats count. The registry README counter maintenance and rejected audit contribute zero IDs.
