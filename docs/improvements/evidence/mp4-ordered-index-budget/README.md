Accepted FVID-0443: omit redundant suffix storage for strictly ordered MP4 video.

The authored 150 ms reproducer contains 150000 16x16 VP9 keyframes at a 1 MHz container clock. Before the fix, a small same-codec control passed under a 2 MiB decoder/reorder budget, while the ordered dense movie failed specifically with `MP4 reorder index exceeds budget` (four controls passed, one acceptance failed). The signed-CTTS companion remains a valid reordered movie under a roomy budget and correctly refuses the tight budget.

Strict presentation order makes the suffix minimum equal to the next immutable sample timestamp. The implementation uses that bound directly and retains the charged suffix vector for reordered or equal timestamps. A private safe probe measures actual Vec capacity and checks its budget charge: ordered storage falls from 1200000 bytes to zero; reordered storage remains 1200000 bytes. Public tests verify all 150000 pictures, timestamps, durations, repeated opens, seeks, rewind and EOF. Zero reorder budgets and intrinsic codec memory limits still refuse input.

An initial 50000-frame/512 KiB witness was rejected because its small control also hit the intrinsic VP9 picture budget. Its generator, manifest and log remain archived as rejected evidence; the corrected regression preserves that legitimate refusal. It contributes no separate improvement.

Qualification: 120 integration suites / 563 passes, root MP4 58 passes, root WebM 67 passes, media 547 passes; four duplicate events excluded, yielding 1231 distinct passing checks. Two existing ignored tests remain unchanged. Core and player locked/offline builds passed. Focused and measurement repeats are excluded from the total. Fixture regeneration is byte-identical; ordinary tests require neither FFmpeg nor network.

The predeclared CPU guard permits at most 10% median regression in opening, navigation and actual seek plus RGB. Seven interleaved baseline/after pairs, 10000 queries each, exclude warmups and use preserved default-release binaries. Navigation increased 4.33%, within that guard; seek plus RGB was effectively unchanged. See cpu-comparison.json for every sample. The primary result is retained-index memory and tight-budget admission, not a CPU speedup. Decoder/reorder budget excludes demux metadata, input buffers and total process RSS. No GPU, high-resolution or whole-player throughput claim.
