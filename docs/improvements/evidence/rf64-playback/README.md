## Container semantics and bounded implementation

The primary [EBU Tech3306 RF64 specification](https://tech.ebu.ch/docs/tech/tech3306v1_1.pdf),section3.4 and AnnexA.2,defines the mandatory first ds64 chunk,the64-bit replacement fields,and optional additional chunk sizes. A finite32-bit field takes precedence;its64-bit replacement is used only for the extension marker. This batch implements those rules for the native Wave reader.

`wav_rf64.rs` validates physical ds64/table availability before building its row index. The index stores an original row ordinal and consumption count using8-byte cells over physically present12-byte table rows. Sorting by ID and original ordinal permits logarithmic lookup without reordering repeated-ID occurrences. No payload buffer is reserved from a declared64-bit size. Extents use checked arithmetic and caller file/data limits before narrowing. Unknown metadata with a truncated claimed payload refuses immediately;data can expose its correct available prefix and subsequently fail EOF validation.

The Wave walker respects the resolved RF64 envelope,recognizes duplicate ds64 descriptors,and replaces data/optional fact markers. Absent fact uses the ds64 sample metadata;finite fact fields retain precedence. PCM sample presentation continues to derive its actual geometry from admitted bytes. RIFF/RIFX keep their existing paths,including the classic unknown-data-length sentinel. For RF64,the same numeric0xffffffff after64-bit resolution is a real data size and does not suppress truncation errors. Missing final metadata is detected independently from missing audio bytes.

External signatures and Limits construction are unchanged. The public declared_bytes value exposes the resolved size;declared_frames includes an RF64 fact replacement. The parser still buffers whole files and default file/data admission limits remain. This is native compatibility within those bounds,not a claim of streaming,full4GiB successful playback,whole-process memory improvement or owned export/loudness RF64 support. Physical devices and visual UI are not qualified.
