# Extended MP4 language tags and bounded Matroska transport

Accepted as FVID-0437 after full qualification. MP4/MOV `elng` is an optional media-header peer whose BCP47 tag overrides a conflicting legacy `mdhd` language. The original shared reader ignores it, losing region, script, extension and private-use information in both metadata inspection and copies. The final original b220fbc346 run passes2 controls and fails6 checks: direct read/probe and eligible AVC copy lose en-AU to eng; the oversized source tag is likewise lost; a separate standard Matroska file with a long LanguageBCP47 value is rejected by the old128-byte IETF limit.

The reader retains well-formed ASCII tags verbatim, including case, registered grandfathered forms, extension/private-use syntax and long variants. Validation is structural, without a network/IANA registry lookup or canonicalization; structurally well-formed unregistered future subtags are retained too. Case-insensitive duplicate variants and extension singletons are invalid. Variant keys use fixed-size ASCII arrays and sorting; private-use parsing streams without a subtag-string list. No performance claim. Version0/flags0 and a NUL-terminated CString prefix (later atom bytes are outside the tag) are required for the optional override. Invalid/empty/duplicate/unsupported metadata falls back to mdhd; mandatory atom extents remain strict. Explicit und clears a conflicting legacy language using the existing empty-string convention.

The shared Matroska writer keeps ordinary three-letter legacy output unchanged. Other tags use LanguageBCP47 (0x22b59d), with legacy Language set to und for older readers. Writer admission and IETF reader strings have an explicit16KiB resource bound; legacy language/control-string bounds remain unchanged. Exactly16384 bytes copy successfully;16385 source bytes remain intact in MP4 read/probe/playback but the copy refuses before writing any output. The independent standard Matroska over-bound witness also retains a resource refusal. This is bounded metadata support, not unlimited language-field support. These downstream integration repairs are part of one language-preservation capability, without extra IDs.

Forty MP4 cases preserve existing metadata fallback;46 preserve valid/well-formed extended tags. Forty-four AVC copies pass acceptance; two separately test over-bound refusal. Both MP4 reader APIs and probe retain exact tags. Every VP9 MP4 preserves exact packets/source clocks/picture planes and real native RGB playback, rewind, EOF and seven seeks. Both native/owned direct copy APIs emit identical Matroska; copied AVC packets/times and actual source/output RGB match, and legacy/IETF fields are checked separately. Independent Matroska inputs isolate IETF precedence and the byte bound, with actual playback/seek. Ordinary tests use committed fixtures, no FFmpeg/network. Optional ffprobe independently verifies all140 movies' packets and raw PTS; command/version/results are retained in independent-packets.json.

Fixture qualification corrections add no count: the first direct-copy test used VP9 on an AVC/HEVC/AAC-only API; eligible authored AVC companions replace only that copy input. A case-preservation pair initially collided on a case-insensitive filesystem; distinct filenames and a generation-time casefold uniqueness guard retain exact case-sensitive tag assertions. The final baseline is rerun on the corrected fixtures and original production sources. No test acceptance is disabled to accommodate either issue.

API/migration: signatures and field types are unchanged. Track.language may now contain an extended BCP47 tag, rather than always a three-letter code; consumers must keep it as text and avoid fixed-width assumptions. Unsupported optional metadata still falls back. Callers of the common Matroska writer must handle explicit refusal beyond16KiB. Other Matroska export paths with smaller pre-existing metadata-description admission limits are not claimed to support arbitrary long tags. Classic Macintosh numeric mdhd language mapping is outside this change. No throughput, whole-process RSS, physical GPU or UI-rendering claim.
