# Equivalent MACE composition-offset runs

Accepted as FVID-0436. CTTS rows encode consecutive samples with the same composition offset. Splitting a row into neighboring equal-offset rows does not change the per-sample mapping. The MACE indexed path instead demands that every encoded row end at a codec block boundary. Thus even an all-zero offset table split after its first raw sample rejects a previously playable MOV/MP4, including its video companion. The original c84a39e8 passes2 grouped-control/malformed-refusal checks and fails1 acceptance at `control-0-zero-split.mp4` with `MACE composition run must cover whole blocks`.

The fix joins consecutive equal-offset runs before the existing whole-block check, without constructing an expanded temporary table. Every row remains positive and bounded by the remaining raw sample count. A genuine offset change within a block remains unsupported and refused; distinct offsets at whole-block boundaries remain separate. Existing checked timestamp arithmetic, resource limits, sample-description handling and codec byte layout remain unchanged. This is a correctness change, with no speed or allocation-performance claim.

Seventeen equivalent pairs (34 valid videos) cover MAC3 mono/stereo, MAC6 mono/stereo, mixed PCM/MACE descriptions, version0 zero/positive offsets, signed version1 negative offsets and genuine whole-block offset changes. Their encoded rows deliberately cut inside blocks. Both indexed reader APIs preserve exact sample clocks, packet bytes, descriptions and coded block sizes. Actual software audio preserves exact float PCM and presentation times through sequential playback, rewind and seven seeks; actual native video retains six analytic neutral16x16 VP9 frames and seek/EOF. Controls are separately accepted before the fix. Twenty separate negative movies retain the original exact refusals for changed-within-block offsets, incomplete blocks, zero rows and excessive sample counts. Existing malformed fixtures/tests are not altered.

`equivalent-raw-mappings.json` independently expands the authored CTTS tables and confirms identical raw mappings and unchanged mdat payloads for all17 pairs. Generation copies only earlier authored synthetic codec data, records its source hashes and uses no encoder/network. Ordinary tests read committed fixtures only. There are55 files including the manifest. One capability counts once; geometry/time-layout variants add no IDs. No device playback, throughput or whole-process RSS claim.
