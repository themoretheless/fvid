# Matroska invisible subtitle frames

RFC9559 sections10.1/10.2 define the Invisible flag for Block and SimpleBlock: the codec SHOULD decode the frame without displaying it. Reference: https://www.rfc-editor.org/rfc/rfc9559.html#section-10.1 . The existing Packet contract also describes this as decode-only reference content. No source example was copied.

The native subtitle reader retains that parsed flag but ignores it when publishing captions. Original4356db8fef passes exact packet/flag/picture validation and fails both caption/actual-seek acceptance tests. The final original-source run adds exact40/60/80ms transition boundaries and gives the same1pass2fail. The earlier original log is preserved separately. The defect concerns presentation of valid, accepted content, not file refusal.

Twenty-four authored16x16 three-picture VP9 files combine invented UTF8, canonical SSA and canonical ASS with explicit-duration BlockGroups and compatibility missing-duration SimpleBlocks. Invisible masks cover none, middle, tail and all captions. Nine exact packet snapshots and both parser ownership paths verify every byte, PTS, duration and Invisible flag. All actual decoded picture bytes,40ms intervals and EOF match the positive control. Native extraction checks exact text and nanosecond bounds; actual seeks check the exact selected picture interval and active text at inclusive starts, exclusive ends and gaps. Positive controls preserve all text. Hidden middle/tail frames do not replace or terminate the previous fallback cue; all-hidden tracks still accept and decode the video with no visible caption.

The correction reads and decodes each caption before suppressing Invisible output, and uses the next visible packet when deriving a fallback endpoint. Current/successor clock normalization, explicit BlockDuration, declared defaults, negative-PTS suppression and full-dialogue compatibility remain covered by related tests. No public interface, parser or codec algorithm changes. No performance or physical-device styling claim is made. Generation is offline pure Python and independent of ordinary tests; no FFmpeg, network or private media/parameters are used. All masks/codecs/block variants count as one visibility improvement.
