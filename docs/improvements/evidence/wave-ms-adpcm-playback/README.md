# Native Microsoft ADPCM WAVE playback

Original source aa2a36013ff550472af1c3c6b6423d1159956c6b refuses WAVE format tag 0x0002. The exact final seven-test stand passes its independent PCM/video and legacy unsupported-extensible/AVI controls, and fails five MS ADPCM tests. The guarded baseline replaces only wav.rs and its Wave64 helper with their original versions, checks for concurrent edits, and restores both candidate files in a finally block. The new MS helper remains present but unlinked on the original source. baseline.json records source and test hashes.

Primary specification: Microsoft/IBM *Multimedia Data Standards Update*, revision 3.0 (1994), “Microsoft ADPCM” and “Fact Chunk”, https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/Docs/RIFFNEW.pdf . The setup has four-bit mono/stereo blocks, decoded samples per block, a coefficient count and signed coefficient pairs. The first seven pairs are fixed; extra pairs are permitted. The fact sample count describes decoded time, rather than the padded encoded extent.

The adapter reuses the existing owned MS ADPCM decoder. It validates WAVEFORMATEX extension length, block geometry, samples-per-block, the standard coefficients and the supported 7..256 table count before retaining setup bytes. Only the interpreted setup prefix is retained (at most 1046 bytes); its cbSize is normalized when unrelated trailing extension bytes are omitted. The same private parsed-format view passes the original fmt body through RIFF/RF64 and Wave64. IMA configuration is also retained from its validated twenty-byte header, and all prior IMA tests remain enabled.

Seventy-three authored positive cases cover RIFF/RF64/Wave64, mono/stereo, small and >2048-frame blocks, standard and added predictor tables, complete/shortened/absent fact counts, and the 256-entry/index255 boundary. Zero residual codes plus predictor1 give an independently specified arithmetic progression. Added predictor7=(0,256) and predictor255 alternate the two header seeds; the Python oracle uses that closed form, independently of Rust reconstruction. Literal PCM16 and f32 controls verify every sample. The fixture generator never calls an encoder, decoder or network.

Tests compare exact decoded samples and sample clocks, raw coded block bytes, full decoder setup, packet/window boundaries, cold/warm seeks, EOF/MAX and rewind. There are 292 actual playback-worker sessions. A private unit checks the 1046-byte retained setup capacity with a sixteen-byte sample run. Other controls require specific metadata refusals; a bad predictor and zero delta must reach the existing decoder's specific Invalid errors. Truncated complete-block prefixes decode exactly and fail EOF, including an unknown-length RIFF data marker with an unfulfilled positive fact count. Native player factory tests exercise both coefficient-table types in all three WAVE envelopes.

A candidate-only integration problem is preserved in extensible-before.log: treating WAVE_FORMAT_EXTENSIBLE MS ADPCM as a classic ADPCMWAVEFORMAT changed its Unsupported classification to Invalid. The explicit unsupported route is preserved so a later valid AVI PCM stream remains selectable. EXTENSIBLE MS ADPCM is not admitted by this capability. Completing this guard contributes no extra ID.

Independent FFmpeg 9.0.2 matches all 24 standard-table complete/absent-fact cases. It emits padded tails for twelve standard-table shortened-fact cases, and refuses added predictor indices 7/255. libsndfile 1.2.2 matches four large-block standard-table complete/absent-fact RIFF cases; its small-block, added-predictor and fact-tail diagnostics are retained separately. These limitations do not weaken native analytic PCM or fact-length expectations. Added-predictor behavior is proved by the specification's simple recurrence, exact configuration bytes and authored analytic samples, not by a false claim of external-decoder agreement.

Compatibility: public functions keep their signatures. The public Coding enum gains MsAdpcm { block_bytes, block_frames }; downstream exhaustive matches must add that variant or use a wildcard, and generic consumers can keep using Pcm block/codec methods. The new private setup storage does not change existing PCM/G711 or predictive behavior. No performance, physical audio-device, complete multi-gigabyte playback, ADM rendering, export or full MS ADPCM profile-conformance claim is made. One native format capability is counted; fixtures, guards, capacity proof, migration notes and candidate authoring repairs are not separate improvements.
