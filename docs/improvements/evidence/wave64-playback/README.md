# Wave64 native playback qualification

The pre-fix source at f2eb89f56cc3660ed9536979cd8a4576d90a8826 rejected authored Wave64 media as `not a RIFF/WAVE file`. `before.log` has one independent RIFF/video control passing and four Wave64 tests failing. The preservation record describes that historical WIP, not acceptance.

Sony/VCS specification: https://mab.greyserv.net/f/sony_wave64.pdf . Wave64 identifies chunks by complete GUIDs, uses little-endian 64-bit sizes including each 24-byte chunk header, and aligns chunks to eight bytes. The whole-file size includes the file header. Unknown GUIDs must be skipped. FFmpeg's independent implementation is https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/wavdec.c .

The native parser reuses WAVE format, padding-bit, PCM geometry, predictive-code frame admission, packetization, decoding and seek. Container sizes never determine retained PCM reservation: only the actual borrowed sample prefix is copied. The private extent marker distinguishes finite Wave64/RF64 data sizes from the legacy RIFF sentinel. Public interfaces remain compatible.

The authored fixtures cover 32 cases: 20 integer/float/G711/extensible base profiles, eight invented predictive profiles, and four fact-count variants. GUID-prefix decoys must stay unknown metadata, and odd metadata/data sizes exercise eight-byte alignment. Eight negative controls require specific rejection. EOF tests distinguish complete PCM with missing trailing metadata from truncated data; both 0xffffffff and 0x100000000 declarations play the exact available 4097-frame prefix under explicitly raised limits and fail EOF. Default limits reject those declarations. The private storage test checks retained PCM capacity <=8192 and packet capacity <=4096; this is not a claim about peak RSS or complete multi-gigabyte playback.

All 20 base external signals decode byte-identically to independent FFmpeg 9.0.2 float PCM. Rust regressions use checked-in analytic PCM/RIFF controls and invented signals; fixture generation and optional reference decoding are separate and ordinary tests need neither FFmpeg nor network. Actual playback-worker tests run 128 sessions across seek targets and EOF. Native player factory and extension admission are tested separately. Physical audio-device playback, visual UI changes, streaming large files, and unrelated owned-media exports are not qualified here.

Initial qualification launch logs are retained as authoring diagnostics: misplaced arguments filtered integration tests and binary entry-point tests contained zero tests. Neither zero-test launch counts. Final qualification uses explicit executed-test counts and library player tests. The source freeze covers the prior RF64 source set plus this capability's sources and fixtures.
