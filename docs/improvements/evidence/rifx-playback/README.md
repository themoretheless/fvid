## Byte order and API scope

The joint IBM/Microsoft [Multimedia Programming Interface and Data Specifications1.0](https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/Docs/riffmci.pdf), chapter2,describes RIFX as the Motorola-order counterpart of RIFF. This establishes the base byte-order convention;it does not qualify every later WAVE codec extension. Local independent decoding supplies an additional interoperability check for the16 authored classic PCM,float and G711 cases.

The Wave parser now reads RIFX numeric chunk lengths and fact counts in big endian. A fixed16-byte format header buffer normalizes classic scalar fields for the same existing geometry validator. Packet payload bytes are retained verbatim. Integer PCM uses its existing big-endian descriptor. Float readers expose fl32/fl64 plus the existing big-endian marker,as the AIFF path already does. Unsigned8 and G711 retain byte-wise sample semantics.

`Wav::is_big_endian()` is an additive raw-parser API. Existing RIFF callers retain their behavior. For float data,raw consumers must combine stored precision with this byte-order property,or use the AudioStream codec/extra-data descriptor. Pcm construction and existing public signatures are unchanged. There is no new decoder algorithm or sample-byte normalization.

Coverage is native WavAudioReader/player audio. RIFX extensible headers and other codings remain explicit Unsupported refusals. The owned export/loudness inspection paths retain their earlier RIFX refusal;this batch does not claim to complete all RIFX public APIs. Physical audio hardware and visual UI are not qualified.
