# Fvid против FFmpeg: фактические измерения

Дата UTC: 2026-09-04T22:26:29.714997+00:00. Платформа: macOS-26.7-arm64-arm-64bit-Mach-O / arm64. CPU model: unavailable in sandbox. Версии: ffmpeg version 9.0.1 Copyright (c) 2000-2026 the FFmpeg developers; rustc 1.98.0-nightly (57d06900f 2026-05-27).

Проверка: 12 комбинаций формата/операции (420/422/444 × copy/hflip/vflip/crop+hflip+vflip), по 7 кадров. Сравнены размеры, число кадров и SHA-256 декодированных planar payload всех трёх вариантов. Совпало побайтно. Это небольшой синтетический корпус, не conformance suite.

Бенчмарк: 720p/180 кадров, 1080p/120, 4K/60; YUV420p testsrc2, чтение локального Y4M и запись Y4M в null sink. В каждой комбинации один прогрев и 7 раундов со случайным порядком трёх команд (seed 451). Тест CPU-only, warm cache, без кодирования в H.264/AV1, без GPU, без fsync. Замер включает startup процесса; интервалы короткие. RSS получен отдельно для каждого дочернего процесса через wait4, единицы macOS — байты. Модель CPU недоступна из sandbox; её не угадывали.

Основная baseline — **FFmpeg с обычными настройками**, а не искусственно ограниченный одним потоком. Однопоточный вариант — дополнительный диагностический столбец.

## Вывод

Прототип выигрывает часть коротких задач и комбинированный crop+отражения, но проигрывает FFmpeg default в 4K copy/hflip/vflip. Поэтому результаты не подтверждают общий тезис «Rust быстрее FFmpeg». Простота запуска и упаковки тоже влияет на измерение. Ни новый codec, ни универсальное преимущество scheduler здесь не проверялись.

FFmpeg уже умеет crop/vflip через frame views. Текущий Fvid всегда материализует выходной frame buffer. Следующая осмысленная гипотеза — убрать эту копию там, где downstream допускает view, и отдельно измерить длительную обработку в памяти.

## Воспроизведение

```sh
cargo build --release
python3 scripts/benchmark.py
python3 scripts/write_reports.py
```

Нужны Rust, Python 3, FFmpeg; RSS-часть сценария использует POSIX wait4, приведённые единицы интерпретированы для macOS. `benchmarks/results.json` содержит все 252 индивидуальных времени (12×3×7), RSS, версии, точные команды и 12 контрольных подписей. Входы восстанавливаются из указанных команд testsrc2; их хеши и хеши локального Rust-кода записаны в provenance.json. После изменения исходников требуется новая сборка и новый запуск.

## Что ещё не измерено

- Длительная установившаяся скорость и confidence intervals; cold cache/физический диск, pipe-to-pipe и durable output.
- H.264/HEVC/AV1/AAC, качество на одинаковом битрейте, другие типы видеоматериала.
- GPU, переносы поверхностей, задержка live, масштабирование scheduler.
- Другие ОС/процессоры и сравнение с выбранными 632 проектами. Они исследованы как источники архитектурных решений, а не пробенчмарканы.
