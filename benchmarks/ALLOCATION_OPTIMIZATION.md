# Уменьшение аллокаций

Каталог 11 MCP-инструментов теперь строится один раз через OnceLock. Поиск возвращает Tool с общей Arc-схемой; проверка имени не клонирует Tool. Каталог общий для серверов, HTTP-сессий и потоков. tools/list по-прежнему выделяет список ответа, а сериализация и выполнение запросов имеют собственные аллокации.

| Прогретый синхронный сценарий | Аллокации до | После | Сумма запрошенных байтов до → после |
|---|---:|---:|---:|
| 1000 поисков известного инструмента | 1 965 000 | 0 | 254 507 000 → 0 |
| 1000 поисков неизвестного инструмента | 1 965 000 | 0 | 254 507 000 → 0 |
| CPU Y4M hflip, 1 кадр 64×32 | 13 | 13 | 3480 → 3480 |
| CPU Y4M hflip, 1000 кадров 64×32 | 13 | 13 | 3480 → 3480 |

CPU уже переиспользует кадровый буфер: в проверенном сценарии число выделений не растёт с числом кадров. Эти 13 выделений относятся к запуску обработки. Числа MCP не являются измерением полного запроса или скоростью обработки видео. Сумма запрошенных байтов не означает одновременное потребление памяти.

В wgpu-пути канал завершения map_async создаётся один раз на GpuProcessor и переиспользуется для upload/readback. Прежде новый sync_channel создавался при каждом map: два создания на кадр при одном upload/download. Сам callback и внутренние структуры wgpu/драйвера по-прежнему могут выделять память; их сокращение количественно не измерено. Последовательный протокол и отравление pipeline после ошибки предотвращают использование запоздавшего ответа следующим кадром.

Проверено: root all-features tests, Clippy, общий указатель схемы между отдельными серверами в разных потоках, MCP stdio и HTTP, реальный Metal на Apple M4 Max. Цепочка 50 кадров × 2 фильтра совпадает с эталоном; 50 загрузок, 50 выгрузок, 100 проходов.

Измеритель [allocation_probe.rs](../scripts/allocation_probe.rs) использует счётчик GlobalAlloc только в отдельном исполняемом тестовом процессе. Производственная библиотека сохраняет forbid(unsafe_code). Счётчик учитывает Rust alloc/alloc_zeroed/realloc, но не native malloc, GPU-аллокатор или освобождения. Прогрев, подготовка входа и печать находятся вне измеряемого участка.

В текущем checkout измеритель собирался так (имя rmcp rlib зависит от сборки):

```sh
cargo build --offline --release --features mcp
rustc --edition=2024 -O -C lto=thin scripts/allocation_probe.rs --extern fvid=target/release/libfvid.rlib --extern rmcp=target/release/deps/librmcp-a9699e8af5d65251.rlib -L dependency=target/release/deps -L native=/opt/homebrew/lib -o /private/tmp/fvid-allocation-after
/private/tmp/fvid-allocation-after
```

Baseline собран до изменений тем же измерителем и сохранён как /private/tmp/fvid-allocation-before; временный файл может исчезнуть при очистке ОС. [Сырые результаты и хеши](allocation-results.json). Старые отчёты скорости относятся к старым бинарникам; ускорение времени выполнения этим замером не утверждается.
